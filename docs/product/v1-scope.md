# 行笺 v1 产品范围

来源：TeslaMate 仓库 `grafana/dashboards/` 的实际面板（20 个顶层 dashboard，其中 `database-info` 面向管理员，不在范围内）。原则是**每个数字都能追溯到某个面板或表字段**，不自造口径。

## 定位

TeslaMate 数据在手机上的第一眼体验：打开即见车况与近期行程/充电，下钻能看到曲线与地点。不是 Grafana 的像素级复刻，也不是车辆控制 App。

## 核心屏幕（v1 必做）

| # | 屏幕 | 内容 | 来源面板 |
|---|---|---|---|
| 1 | 车辆切换 | 多车列表、切换、显示数据新鲜度 | 全局 `$car_id` 变量 |
| 2 | 首页概览 | 当前状态（在线/休眠/充电）、电量、续航（额定/估算）、今日与本月里程、最近一次行程、最近一次充电、固件版本 | `overview`、`mileage` |
| 3 | 行程列表 | 倒序、按时间段筛选、起终点、距离、时长、电耗 | `drives` |
| 4 | 行程详情 | 地图轨迹、速度/电量/海拔曲线、起终点地址与围栏、最高/平均速度、内外温度 | `drives`、`trip` |
| 5 | 充电列表 | 倒序、地点、电量区间、能量、费用、时长、AC/DC | `charges` |
| 6 | 充电详情 | 功率/电量曲线、费用明细、温度 | `charges`、`charge-level` |
| 7 | 统计 | 按周/月/年/自定义：行程数、总里程、净/毛电耗、充电次数、总能量、平均电价、AC/DC 占比 | `drive-stats`、`charging-stats`、`statistics` |

## 延后（v1 不做，保留接口余地）

- 电池健康与衰减曲线（`battery-health`、`efficiency`、`projected-range`）
- 时间线（`timeline`、`states`）
- 地点与地理围栏管理（`locations`、`visited`）
- 固件更新历史（`updates`）
- 吸血鬼耗电（`vampire-drain`）
- 温度专项（`temperatures`）

## 明确的非目标

- **车辆控制**（开锁、空调、鸣笛、召唤）：需要 Tesla token，与 ADR-0002 冲突。
- 实时流 / 秒级刷新：数据新鲜度上限就是 TeslaMate 的轮询结果。
- 数据写入与修正：不提供「修改行程」「删除充电记录」。
- Grafana 嵌入、iframe、面板配置。
- 多用户、共享、社交、排行榜。
- 推送通知（v1 不做，后续可基于用户自建通道）。
- SaaS 托管：见 ADR-0003。

## 假设与限制

1. 用户已有可用的 TeslaMate，且库里有历史数据；空库只显示空状态。
2. 车辆休眠期间没有位置点，图表会出现空洞；如实呈现。
3. 一个站点可有多辆车。
4. 数据新鲜度可能落后数分钟到数小时，App 必须显示「最后更新」。
5. 单位在服务端统一为公制，客户端按系统设置换算。
6. 指标口径以 TeslaMate 已写入的聚合列和 `docs/api/v1-surface.md` 的推导规则为准；服务端只做聚合、裁剪与约定的能量/电耗推导，不引入另一套口径。

## 成功标准

- 首屏（概览）在 4G 网络下冷启动 ≤ 2s，热启动 ≤ 800ms。
- 同一车辆、同一时间范围，页面数字与 Grafana 对应面板一致；口径差异必须写进文档而不是「看起来差不多」。
- 行程详情在 5 万条行程、50 万位置点的库上，端到端 ≤ 1.5s。
- 服务端对 TeslaMate 库的写操作为零（由只读角色强制）。
- 安装路径：在现有 TeslaMate compose 中追加一个 service + 三条环境变量即可启动。

## 待定

- 地图底图与轨迹渲染方案（Flutter 侧，需在国内可用）。
- 首页是否需要「充电中」的实时进度（依赖 TeslaMate 采样频率）。
- v1 是否包含多车对比。
