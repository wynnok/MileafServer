# ADR-0003: 单租户自托管分发

- 状态：Accepted
- 日期：2026-10-21

## 背景

产品计划商业化。Tesla 凭据属于高敏感资产，Mileaf 不做 SaaS、不托管用户数据。因此交付形态只能是「用户自己部署、Mileaf 只提供成品镜像」：用户在自己的网络里运行 Mileaf Server，直连自己的 TeslaMate 库，凭据始终不离开用户环境。

## 决定

1. **单租户**：一个 Mileaf Server 实例只服务一个站点。不做注册、多用户、组织、共享。
2. **交付物**：多架构（amd64/arm64）Docker 镜像 + 一段 `docker-compose` 片段。用户只需追加一个 service，不改动 TeslaMate 的 compose 结构。
3. **本地状态最小化**：不引入第二个数据库。唯一持久状态是挂载卷里的一个 `state.json`（权限 `0600`），只存访问口令哈希与已签发 token 的指纹。业务数据不落盘。
4. **鉴权**：首次启动用一次性初始化流程设置访问口令；之后 `POST /v1/auth/login` 换取长期 Bearer token，存于 Flutter secure storage。无 OAuth、无第三方登录、无找回密码（用户可删除 state 文件重置）。
5. **不内置隧道，不内置遥测**：服务只监听容器内 HTTP；TLS 与公网暴露由用户自备的反向代理或 VPN 完成。不做任何外联上报。

## 远程访问

v1 只支持两种用户自备的接入方式，服务端不内置隧道、不申请证书、不代管域名：

- **Tailscale**（推荐）：Mileaf Server 与手机在同一 tailnet，App 直连 `http://<tailscale-ip>:<port>` 或 MagicDNS 名称。
- **公网 IP / 自有服务器**：用户自行完成 TLS 终止（反代或负载均衡），Mileaf Server 只暴露明文 HTTP 给可信上游。

文档提供这两种方式的 recipe。若将来要做「开箱即用的公网访问」，需另立 ADR，因为那会把 Mileaf 拉进域名、证书、隧道中转的运维与合规范围。

## 影响

- 用户体验门槛：必须自己会跑 Docker 和配置安全访问；这是过滤非目标用户的手段，也是商业化的入场费。
- 无法做集中式分析、跨用户排行榜、云端推送通知（可后续用用户自己的推送服务解耦）。
- 升级靠用户拉新镜像；服务需要提供 `/v1/meta` 让 App 显示版本与兼容性。
- 镜像分发与授权模式（私有镜像仓库、license）不在本 ADR 内。
